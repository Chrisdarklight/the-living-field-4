# The Living Field — site starter

This is a static, no-build-step website: plain HTML/CSS/JS, no framework, no server required to run it. Open `index.html` in a browser and it works as-is.

## What's built

- **Home** (`index.html`) — hero, mission, teasers for Electroculture/Water Energetics/Radionics, Our Shared Mission, and an Alchemical Formulations section introducing The Collections (Cultivate Elevate, Elemental Wizdom, Sacred Heart Plant Essences) — see "0. Image sources" and "7. The Body section" below
- **Education hub** (`education/`) — hub page + one full sample guide (`education/guides/electroculture-antenna-basics.html`)
- **Shop** (`shop/`) — hub page with Electroculture equipment, Training, Water Energetics and Radionics categories: one sample electroculture product (`shop/electroculture/cw-antenna.html`), one sample training course + bundle (`shop/training/antenna-installation-course.html`), one Water Energetics product (`shop/water-energetics/cloud-sea-aqua-inductor.html`), and two Radionics products (`shop/radionics/heaven-earth-broadcaster.html`, `shop/radionics/murmuration-transmitter.html`)
- **Alchemical Formulations** (`alchemical-formulations/`) — wellness/supplement vertical, renamed from `body/` on 2026-09-15 (see the dated sweep entries below; a `_redirects` file at the site root 301s the old `/body/*` address), see "7. The Body section" below for background
- **FAQ** (`faq/`) — accordion FAQ with schema markup
- **Contact** (`contact/`) — contact form, wired to Netlify Forms (see below)
- **Legal** (`legal/terms.html`, `legal/privacy.html`) — starter templates only, **must be reviewed by a solicitor before launch**; (`legal/disclaimer.html`) — live, real content (not a placeholder), the food-supplement/equipment disclaimer, linked from every page's footer and from every "Email to order" button
- **Basket** (`basket/`) — new 2026-09-16, real multi-item shopping basket (browser-stored, add from any product, pay for everything in one Stripe Checkout) — see "2. Stripe checkout — the real basket" below for what's needed to switch it on
- Shared design system in `assets/css/style.css`, shared behaviour in `assets/js/main.js`, new basket behaviour in `assets/js/cart.js`
- `robots.txt` and `sitemap.xml` for search engines
- `netlify/functions/create-checkout-session.js` — a Netlify Function (small server-side code, not part of the static site itself) that talks to Stripe to create the basket's Checkout Session; `netlify.toml` tells Netlify where to find it

## Security checks

Standing practice for every future round of changes on this site: before anything new ships, sweep the changed files for the basics —
- Every `<script src>` should point only to this site's own `assets/js/*` (relative, same-origin) or a small, named allowlist of trusted third parties (currently: Google Fonts, Stripe payment links, YouTube-nocookie embeds). Anything else gets a hard look before it stays.
- No `eval(`, `document.write`, `atob(`/base64-decoded code, `new Function(`, or `javascript:` links anywhere.
- New images are checked with `file` to confirm they're genuinely the image type their extension claims, not something disguised.
- No file types other than the expected HTML/CSS/JS/image/text set show up anywhere in the project.
- Any newly-referenced external domain (via `url()`, `@import`, `<script src>`, `<iframe src>`, or link `href`) gets called out explicitly rather than passed over quietly.

### 2. Stripe checkout — the real basket
As of 2026-09-16 this site has a real, multi-item basket (`basket/`, `assets/js/cart.js`) rather than per-product Stripe Payment Links — CJ confirmed customers need to add several different products and pay for the total in one go, which Payment Links can't do on their own. To switch it on:

1. **Deploy via a GitHub repo connected to Netlify**, not manual zip uploads — the basket needs a Netlify Function (`netlify/functions/create-checkout-session.js`), and Functions only run on Git-connected or CLI deploys. See "Where we left off" above for the exact handoff steps needed to get this codebase onto GitHub.
2. In Netlify: **Site settings → Build & deploy → Link repository** to the new GitHub repo.
3. In Netlify: **Site settings → Environment variables**, add `STRIPE_SECRET_KEY` using the **secret** key from the Stripe Dashboard (Developers → API keys). Never put this key in any file in this repository, any chat message, or anywhere else outside Netlify's own environment variable settings.
4. In Stripe: create a **Product** and a **Price** for each item you sell (Dashboard → Product catalog). Copy each Price ID (`price_...`).
5. Wire each product page's "Add to basket" button to its Price ID — a `data-price-id="price_..."` attribute is all `cart.js` needs; ask for this to be done once the Price IDs exist.

No prices or amounts are ever sent from the browser — only Price IDs, which Stripe itself resolves to the real, trusted price server-side. This is safer than the raw price being editable in someone's browser.

If Stripe or Netlify's exact dashboard steps have moved since this was written, their own current documentation (stripe.com/docs, docs.netlify.com) is the source of truth — this section describes the architecture, which doesn't change often, more reliably than it describes today's exact button labels.
